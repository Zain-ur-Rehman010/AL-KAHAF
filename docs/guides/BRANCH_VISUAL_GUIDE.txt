📋 TWO WORKFLOWS TO CHOOSE FROM
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

OPTION 1: Simple (Work Only on Main)
────────────────────────────────────────

    main ←─────┐
      │        │
      ├─→ edit files
      ├─→ commit
      ├─→ push
      │        │
    main ←─────┘

Commands:
    $ git add .
    $ git commit -m "Update homepage"
    $ git push origin main

✅ Pros: Simple, no confusion
❌ Cons: Can't experiment safely


OPTION 2: Feature Branches (Recommended)
─────────────────────────────────────────

    main (stable)
      │
      ├─→ create feature/login
      │        │
      │   feature/login
      │        │
      │        ├─→ work on login
      │        ├─→ commit changes
      │        ├─→ test
      │        │
      │   merge ←┘
      │
    main (updated)
      │
    delete feature/login

Commands:
    $ git checkout -b feature/login
    $ git add .
    $ git commit -m "Add login page"
    $ git checkout main
    $ git merge feature/login
    $ git branch -d feature/login

✅ Pros: Safe experimentation, organized
❌ Cons: Slightly more complex

🔄 COMMON OPERATIONS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Check Current Branch:
    $ git branch
    
    Output:
      backend
      frontend
    * main     ← The * shows you're here
      topbar


Switch to Different Branch:
    $ git checkout frontend
    
    Result:
      backend
    * frontend  ← Now you're here
      main
      topbar


Create New Branch:
    $ git checkout -b feature/new-thing
    
    Result:
    * feature/new-thing  ← New branch created and switched
      main


Merge Branch:
    $ git checkout main           # Go to main
    $ git merge feature/login     # Bring in changes
    
    Result: Changes from feature/login are now in main


Delete Branch:
    $ git branch -d feature/login  # Local
    $ git push origin --delete feature/login  # Remote

🚨 WHAT WENT WRONG (Your Recent Issue)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Problem: When you merged backend branch, it broke frontend

Why?
    main branch had:
        frontend/index.html ✅
        frontend/about.html ✅
    
    backend branch had:
        frontend/src/pages/index.html ❌ (different location!)
        frontend/src/pages/about.html ❌ (different location!)
    
    When merged:
        Git got confused about which version to keep
        Your frontend paths broke

Solution Used:
    We only merged the backend/ folder
    Left frontend/ folder untouched
    Result: Both work! ✅

💡 BEST PRACTICES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

1. Before Switching Branches:
   ✅ Commit your changes first
   ❌ Don't switch with uncommitted changes

2. Before Merging:
   ✅ Test your code
   ✅ Switch to destination branch (usually main)
   ❌ Don't merge broken code

3. Branch Naming:
   ✅ feature/user-login
   ✅ fix/payment-bug
   ✅ update/homepage
   ❌ test
   ❌ new
   ❌ branch1

4. Commit Messages:
   ✅ "Add user authentication with JWT"
   ✅ "Fix login button alignment"
   ✅ "Update course listing page design"
   ❌ "changes"
   ❌ "fix"
   ❌ "update"

5. Daily Routine:
   Morning:
   $ git pull origin main
   
   During work:
   $ git add .
   $ git commit -m "Clear message"
   
   End of day:
   $ git push origin main

🎯 REMEMBER
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Git branches are like parallel universes for your code.
Each branch is a separate timeline where you can make changes.
When ready, you merge timelines back together.

main = your stable, production code (always working)
feature branches = your experiments (safe to break)

Always know which branch you're on: git branch
Commit before switching branches
Keep main branch clean and working
Delete branches after merging
